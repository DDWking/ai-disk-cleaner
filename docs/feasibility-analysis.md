# 项目可行性分析：AI 磁盘清理软件

> 核心链路：**扫盘（快）→ 解析文件元数据 → AI 判断文件是什么/多久没用 → 给清理建议 → 用户确认后清理**

---

## 1. 结论（先说）

**可行，且非常适合 2 人学生项目。** 但要控制范围：先做"规则清理 + 元数据判断"跑通全链路，AI 只做"解释和兜底建议"，别一上来就啃 MFT 底层。

推荐落地顺序（分阶段，别一上来全做）：

| 阶段 | 做什么 | 目的 |
|---|---|---|
| Phase 1（1–2 周） | 递归扫盘 + 取元数据 + 文件类型识别 + **规则**清理建议 | 跑通完整产品链路 |
| Phase 2（2–4 周） | 接入 LLM，对文件做"分类 + 用途 + 清理理由" | AI 能力落地 |
| Phase 3（2–4 周） | MFT 加速扫描 + 树图(Treemap)可视化 | 性能 + 亮点 + 复试硬货 |

---

## 2. 技术可行性（逐个拆）

### 2.1 扫盘：为什么 WizTree 快，你该怎么选

WizTree 不是一个个遍历文件，而是**直接读 NTFS 的 MFT（Master File Table，主文件表）**，几秒扫完百万文件。你有 4 条路线：

| 方案 | 速度 | 权限 | 复杂度 | 备注 |
|---|---|---|---|---|
| A. 直接读 MFT | 秒级 | 需管理员 | 高 | WizTree 同款，复试最硬核 |
| B. USN 日志 `FSCTL_ENUM_USN_DATA` | 秒级 | 需管理员 | 中 | 比 A 好写，仍要 Windows API |
| C. 递归遍历（`os.walk`/`FindFirstFile`） | 分钟级 | 无 | 低 | MVP 首选 |
| D. 借 Everything 命令行 `es.exe` | 秒级 | 无 | 最低 | 落地最快，但依赖第三方、讲不透原理 |

**建议：Phase 1 用 C（快出成果），Phase 3 升级到 A/B（吃透原理，写进复试）。**

### 2.2 文件元数据（"什么时候产生/多久没用"）

- **创建时间 / 修改时间**：直接能拿，可靠。
- **访问时间（"多久没用"）**：⚠️ **Windows 10 起默认关闭了最后访问时间更新**（`NtfsDisableLastAccessUpdate=1`），所以"最后访问时间"经常是假的。
- **替代方案**：用"最后修改时间"或"文件出现在回收站/下载目录的时长"来近似"多久没用"，并在产品里诚实标注。

### 2.3 文件类型识别

- 扩展名（不可靠，可伪造）
- **魔数（magic bytes）**：读文件头几个字节判断真实类型，如 `MZ`=PE 可执行、`PK`=zip/docx、`%PDF`=PDF
- 推荐用现成库：Python `python-magic`，C# 自己读头 4~8 字节即可

### 2.4 AI 分析

- **输入**：文件名 + 完整路径 + 类型 + 大小 + 创建/修改时间 +（可选）文件头前几百字节。
- **输出**：①这是什么类型的文件 ②大概用途 ③是否疑似可清理 + 理由 + 风险等级。
- **关键决策——隐私与成本**：
  - **不要把文件全文发给 AI**（隐私泄露 + 成本爆炸），只发元数据和文件头摘要。
  - 批量处理 + 结果缓存，避免重复计费。
  - 用 DeepSeek / OpenAI 等 HTTP API 即可，2 人项目成本极低（几千个文件几分钱级别）。

### 2.5 清理执行（安全第一）

- 默认**移入回收站**，绝不直接 `Shift+Delete`。
- 内置**白名单**：系统目录（`C:\Windows`、`Program Files`）、受保护路径，AI 说删也不删。
- **AI 建议 + 规则兜底 + 用户最终确认** 三层，把误删风险压到最低。

## 3. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 管理员权限 | MFT/系统盘读取受限 | 分阶段：先普通遍历，后申请管理员 |
| AI 幻觉导致误删建议 | 误删用户文件 | 规则兜底 + 回收站 + 白名单 + 用户确认 |
| 隐私（路径/文件名敏感） | 泄露 | 默认不上传文件内容，本地处理，隐私声明 |
| API 成本/限流 | 超预算 | 批量 + 缓存 + 只发摘要 |
| 百万文件性能/内存 | 卡死 | 流式处理，不全量加载；用堆求 Top-K |
| 仅支持 NTFS | 换文件系统失效 | MVP 只承诺 Windows/NTFS，写清范围 |

---

## 4. 技术栈推荐

| 方案 | 组合 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | C# / .NET 8 全栈：扫描+界面+调 LLM HTTP | WizTree 同款语言，可吃透 MFT（复试硬货），一门语言全栈 | 学习曲线略陡 |
| B（最快 MVP） | Python 全栈 + Everything/es.exe + openai SDK | 3 天出 demo | 底层原理讲不透，复试吃亏 |
| 折中 | Phase 1 用 Python 验证链路 → Phase 3 用 C# 重写扫描核心 | 两者兼得 | 要重写一次 |

> 我的建议：**A 或折中**。你们要的不只是能跑的软件，还有复试能讲透的原理，C# 直接 P/Invoke 读 MFT 这条线含金量最高。

---

## 5. 工作量估算（2 人）

- Phase 1：1–2 周
- Phase 2：2–4 周（调 prompt、控制成本、做安全兜底）
- Phase 3：2–4 周（MFT + 可视化）

**总计：1.5–3 个月业余时间可做出一个能演示、能讲原理的版本。**

---

## 6. 一句话总结

**可行、值得做、难度可控**：难点不在 AI（调 API 很简单），而在**扫描性能、安全兜底、和把底层原理讲清楚**——而这三点恰恰是复试的得分点。
